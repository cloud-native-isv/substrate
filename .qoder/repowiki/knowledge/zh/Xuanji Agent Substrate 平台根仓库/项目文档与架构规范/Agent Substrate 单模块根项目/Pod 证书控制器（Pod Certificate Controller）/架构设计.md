模块采用 `cmd` + `internal/` 的标准 Go 应用结构：
- `main.go` 作为入口，解析 pflag 参数（kubeconfig、in-cluster、sharding-*、CA pool 文件路径），构建 kubernetes.Interface，启动 rendezvous 分片协调器，并分别实例化 servicedns 与 podidentity 两个 SignerImpl 及其对应的 signercontroller。
- `signercontroller/signercontroller.go` 定义核心控制循环：通过 certinformersv1beta1 监听 PodCertificateRequest，使用 workqueue.TypedRateLimitingInterface 去重与退避重试，按 SignerName 路由到具体 handler；同时周期性确保 ClusterTrustBundle 处于期望状态。
- `rendezvous/rendezvous.go` 基于 K8s Lease 对象实现 FNV-1a 64 位 rendezvous 哈希分片，使多副本间对同一工作项达成一致归属，避免重复处理。
- `podidentitysigner` 与 `servicednssigner` 各自实现 `signercontroller.SignerImpl` 接口：前者从 PCR 提取 Pod/ServiceAccount/Node 信息生成 SPIFFE URI 客户端证书，后者扫描同名命名空间下匹配该 Pod 的 Service 以填充 DNS SAN。
- `podcertificate/publickey.go` 提供统一的公钥提取逻辑，兼容 StubPKCS10Request 与过渡期的 PKIXPublicKey 字段。
- 依赖方向单向：main → signercontroller → (podidentitysigner|servicednssigner) → podcertificate；rendezvous 被 controller 与 hasher 共享，不反向依赖业务 signers。
