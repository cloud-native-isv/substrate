模块以 Kustomize 为核心编排工具，采用分层叠加结构：
- `base/` 作为基础层，通过 `resources` 引用根目录下的核心 YAML（ate-api-server、ate-controller、atelet、atenet-dns、atenet-router、valkey、pod-certificate-controller、ate-otel-config），构成最小可用集群。
- `components/agentgateway/` 声明为 `Component`（kustomize.config.k8s.io/v1alpha1），通过 JSON Patch 将 atenet-router 的第二个容器替换为 agentgateway，并注入 Envoy 配置 ConfigMap，实现可选的功能扩展。
- `kind/` 是面向本地 Kind 集群的开发覆盖层，引入 rustfs（S3 兼容存储）、OpenTelemetry Collector 和 Prometheus，并通过 inline patch 注入 OTEL 环境变量与调试参数；其 ate-otel-config.yaml 覆盖 base 中的同名 ConfigMap，使所有组件指向集群内 Collector。
- `token-client/` 是认证方式覆盖层，将 ate-controller 和 atenet-router 从客户端证书切换为 projected ServiceAccount Token 认证，挂载到固定路径 `/run/ateapi-token/token`。
- 顶层独立 YAML（如 ate-install/*.yaml）存放各组件原始定义，被 base/kind 等 overlay 引用。
- 依赖方向单向向下：overlay → base → 原始 YAML；component 仅对已有资源做 patch，不反向依赖 overlay。
