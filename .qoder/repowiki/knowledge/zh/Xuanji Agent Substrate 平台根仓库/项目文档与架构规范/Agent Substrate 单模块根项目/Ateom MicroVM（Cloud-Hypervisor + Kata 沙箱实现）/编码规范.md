- 每个 RPC 方法在 AteomService 上通过 `s.lock.Lock()` 串行执行，确保 run/checkpoint/restore 生命周期不可并发调用。
- 所有子进程启动统一走 `reaper.Run` / `reaper.RunCombined`，以保证同步子进程的 wait 不被 SIGCHLD reaper 抢先回收。
- 错误返回使用 `fmt.Errorf("while ...: %w", err)` 包裹上下文信息，gRPC 层通过 `status.Error(codes.X, msg)` 映射到标准错误码。
- 资源清理采用 defer + retErr 守卫模式：在函数入口处 defer 一个 cleanup 闭包，仅在发生错误时执行，保证失败路径也能释放 VMM、virtiofsd、网络和设备 FD。
- kata 相关路径遵循固定约定（如 `/run/vc/vm/<id>/clh-api.sock`、`VMDir(id)`、`SharedDir(id)`），通过 `kata.CLHSocketPath`、`kata.VirtiofsdSocketPath` 等辅助函数访问而非硬编码字符串。
- 内核参数拼接使用 `appendKernelParams` 配合 marker 去重，确保 WithDebugConsole / WithAgentDebug 多次调用幂等。
