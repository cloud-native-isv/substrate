模块以 `main.go` 为入口，使用 `sigs.k8s.io/controller-runtime` 创建 Manager，注册三个 Reconciler：
- `WorkerPoolReconciler`：监听 `ate.dev/workerpools`，通过 SSA Apply 声明式创建并拥有 `apps/v1.Deployment`，同时同步状态到 CRD Status。
- `ActorTemplateReconciler`：监听 `ate.dev/actortemplates`，通过 `pkg/proto/ateapipb.ControlClient` 调用 ateapi 的 CreateAtespace/CreateActor/ResumeActor/SuspendActor 等 RPC，驱动 PhaseInitial → PhaseResumeGoldenActor → PhaseWaitGoldenActor → PhaseReady 的状态机，最终产出黄金快照。
- `NetworkPolicyReconciler`：监听 WorkerPool，生成仅允许 `ate-system` 命名空间内 `atenet-router` Pod 入站的 NetworkPolicy，并以 OwnerReference 绑定到 WorkerPool。

所有资源更新统一通过 `client.Apply(..., client.FieldOwner(...), client.ForceOwnership)` 进行 Server-Side Apply，避免字段冲突。`workerpool_apply.go` 集中构建 Deployment ApplyConfiguration，按 `SandboxClass`（gVisor 或 MicroVM）分支注入安全上下文、能力集、设备挂载与节点调度约束；OTel 配置通过环境变量透传到 ateom 容器。RBAC 权限通过 `//+kubebuilder:rbac:` 注释声明，由 `gen.go` 中的 `controller-gen` 自动生成至 `manifests/ate-install/generated/`。依赖方向单向：控制器 → k8s API (client-go) + ateapi gRPC，不反向依赖上层业务。
