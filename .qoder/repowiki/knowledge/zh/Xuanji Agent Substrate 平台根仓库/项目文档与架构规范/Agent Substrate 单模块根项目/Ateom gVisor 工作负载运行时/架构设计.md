本模块是单一可执行程序 `ateom-gvisor`，采用按构建标签拆分源码的方式：`main.go`（`//go:build linux`）实现完整逻辑，`main_unsupported.go`（`//go:build !linux`）在非 Linux 平台仅输出一行错误并退出。

- 入口与生命周期：`main()` 解析 pflag 参数后调用 `do(ctx)`，依次初始化 slog 日志、OpenTelemetry 追踪与指标、创建 ateom 目录、设置 cgroup 委派、启动子进程回收器、监听 Unix socket，并注册 gRPC 服务。
- gRPC 服务层：`AteomService` 实现 `ateompb.AteomServer`，通过互斥锁串行化所有 RPC，暴露 `RunWorkload`、`CheckpointWorkload`、`RestoreWorkload` 三个方法，每个方法都遵循“停用网络 → 准备环境 → 调用 runsc → 等待 readyz → 激活网络”的统一流程。
- runsc 封装：`runsc.go` 将外部二进制 `runsc` 包装为 `cmdCreate/cmdStart/cmdCheckpoint/cmdFsCheckpoint/cmdRestore/cmdDelete/cmdState` 等方法，统一注入 `-root`、`-bundle`、`-image-path` 等参数，并通过 `ensureContainerCgroupsPath` 在 OCI spec 中补全 cgroupsPath。
- 网络与隧道：通过 `ateomnet` 创建独立 netns 并配置 veth；`atunnel` 同时提供入站 HTTPS 服务器与透明 TCP egress 代理，由 `activateActorNetworking`/`deactivateActorNetworking` 成对启用/禁用。
- 辅助工具：`internal/ateom/stopwatch.go` 提供可被 slog 直接序列化的计时器结构，用于记录关键步骤耗时。
- 依赖方向：本模块依赖 `internal/actorlog`、`internal/ateinterceptors`、`internal/ateomnet`、`internal/ateompath`、`internal/atunnel`、`internal/imagecache`、`internal/readyz`、`internal/resources`、`internal/serverboot`、`internal/version` 等内部包，不反向依赖上层控制面。
