每个子目录是一个独立的 SKILL，以 `SKILL.md` 作为入口与能力契约，采用统一的三段式结构：`references/` 存放参考文档与 API 说明，`scripts/` 存放可执行脚本（Python/Shell/JS），`templates/` 或 `assets/` 存放模板与静态资源。技能之间通过声明式元数据耦合——`SKILL.md` 的 YAML front matter 定义 `name`、`description`、`skill_id`、`license`、`metadata.author/version`，由上层 Spec Kit 引擎加载并路由到对应技能；跨技能调用通过 `${SKILL_HOME}` / `${SKILL_WORKDIR}` 环境变量引用彼此资源（如 `clone-website-ui` 依赖 `browser-utils`）。技能内部遵循统一路径约定：`${SKILL_HOME}/scripts/*` 为可执行工具，`${SKILL_HOME}/references/*` 为人类可读指南，`${SKILL_HOME}/examples/*` 为示例代码。部分技能还包含独立运行时组件（如 `browser-utils/scripts/bridge/` 的 Chrome 扩展 + WebSocket 桥接、`database-utils/scripts/query.py` 的多协议分发器、`document-utils/scripts/docx/office/` 的 Office XML 解析与验证器），但对外仅暴露为命令行接口供 Agent 调用。所有技能在末尾内置相同的 Feedback 步骤，通过调用 `.specify/scripts/python/feedback-utils.py` 将运行反思持久化到引擎。
