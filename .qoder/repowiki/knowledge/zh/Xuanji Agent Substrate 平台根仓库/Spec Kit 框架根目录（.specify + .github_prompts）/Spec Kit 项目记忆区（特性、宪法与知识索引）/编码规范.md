- 每个特性以三位数字 ID 命名独立 Markdown 文件（如 `001.md`），并通过根 `features.md` 的表格行进行索引与状态同步。
- 特性详情文件统一包含「Overview / Key Changes / Implementation Notes / Future Evolution Suggestions / Related Files / Status Tracking」章节结构，其中状态机表格作为跨命令引用的权威来源。
- 会话、反馈、知识三类条目均通过同构的 `index.json` 元数据文件登记，字段包含 id、file、scope、source、tags、created、summary 等，便于工具批量扫描。
- 特性状态严格遵循 Draft → Planned → Implemented → Ready for Review → Completed 五态流转，且任何回退需显式用户确认，禁止静默降级。
- 自定义 xuanji 分支能力（如 E2B 协议面、Wasm Sandbox）在详情文件中明确标注「xuanji custom」并声明不得提交至上游 main 分支。
- 文档命名遵循 kebab-case 小写路径语义，保留 ALL-CAPS 文件名给 README/LICENSE 等生态约定名称，工具强制文件名（如 `constitution.md`、`glossary.md`）除外。
