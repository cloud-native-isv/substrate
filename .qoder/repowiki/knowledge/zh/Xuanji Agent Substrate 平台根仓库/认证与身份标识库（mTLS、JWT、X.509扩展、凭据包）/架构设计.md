本模块由五个相互协作的 internal 子包组成，依赖方向自底向上：
- `principal` 是最底层公共类型，定义 `PrincipalInfo{ID, Kind}` 并通过 context key 在请求链路中传递已认证主体。
- `credbundle` 负责解析 Kubernetes Pod Certificates 格式的 PEM 凭据包（首块 PRIVATE KEY + 后续 CERTIFICATE），并提供带文件变更检测的 TLS 证书缓存 Loader/ClientLoader。
- `substratex509` 基于 GoogleSubstrate PEN (1.3.6.1.4.1.11129.2.12) 自定义 OID，将 PodIdentity 与 ActorIdentity 以 JSON 编码写入 x509 ExtraExtensions，提供 Add/From 成对函数。
- `localjwtauthority` 实现一个本地 JWT “CA”，通过 ECDSA P256 生成 Authority，并支持 PKCS#8/PEM 私钥的序列化与反序列化。
- `ateapiauth` 是顶层入口：客户端侧通过 `DialOptions` 返回 gRPC DialOption（mTLS 或 Bearer Token 二选一），服务端侧通过 `UnaryServerInterceptor` / `StreamServerInterceptor` 链式验证——优先从 mTLS peer 证书 URI SAN 提取 SPIFFE ID，否则回退到 `VerifyBearerToken` 回调校验 JWT；认证成功后调用 `principal.InjectContext` 注入主体信息。
各包之间仅通过 Go 接口和结构体交互，无全局状态，测试文件与源码一一对应。
