- 每个 gRPC 方法先调用独立的 `validateXxxRequest` 函数进行参数校验，再通过 `toGRPCStatusError` 统一转为 gRPC InvalidArgument 错误。
- 长生命周期操作封装为 `WorkflowStep[Params, Context]` 接口的步骤序列，由 `RunWorkflow` 统一编排，步骤需实现 IsComplete/CheckPrerequisite/Execute/RetryBackoff。
- 对外部依赖（store、listers、kubeClient、dialer）通过构造函数注入，且允许 nil 的 Instruments 作为 no-op，避免调用点判空。
- 错误分类遵循 gRPC codes：NotFound/AlreadyExists/FailedPrecondition/Aborted 等语义化返回，配合 `status.Errorf` 构造结构化错误。
- 指标记录使用 defer 包裹 start 时间，在方法退出时统一调用 `recordLifecycleOp` 或 `recordSchedulerAssignment`，确保成功与失败路径都上报。
- Kubernetes informer 通过自定义 Indexer（byNamespaceAndName、byNode、byWorkerPool）加速查询，而非 ListAll 后过滤。
