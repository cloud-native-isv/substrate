模块以 `service.go` 中的 `Service` 结构体作为 `ateapipb.ControlServer` 的实现入口，聚合持久化层 `store.Interface`、`AteletDialer`（gRPC 到 Atelet 的安全连接）、Kubernetes listers（ActorTemplate/WorkerPool/SandboxConfig）、`ActorWorkflow` 以及 `Instruments` 指标。
- 请求处理按资源拆分：每个实体一组文件（如 `create_actor.go`、`get_actor.go`、`update_actor.go`、`delete_actor.go`），统一通过 `validate.go` 的 `toGRPCStatusError` 将 `field.ErrorList` 转为 gRPC 错误。
- 复杂生命周期（resume/suspend/pause/delete）由 `workflow.go` 中的泛型 `WorkflowStep[Params, Context]` 接口驱动，`RunWorkflow` 实现客户端驱动的向前恢复模式，支持幂等跳过、前置条件检查与版本冲突指数退避重试。
- `dialer.go` 的 `AteletDialer` 基于 k8s informer 缓存，按 worker pod → 节点 → atelet pod 的路径建立 mTLS 连接，使用 SPIFFE ID + PodIdentity 扩展校验对端身份，连接经 LRU 缓存复用。
- `informer.go` 提供 `AteletInformer` 和 `WorkerPodInformer`，为 dialer 和 syncer 构建带自定义索引器的 SharedIndexInformer。
- `syncer.go` 的 `WorkerPoolSyncer` 监听 Worker Pod 事件，将 Kubernetes 状态同步到 store，并做孤儿清理。
- `workload_spec.go` 负责将 CRD `ActorTemplate` 转换为 ateletpb `WorkloadSpec`，含环境变量解析（SecretKeyRef）与外部卷映射，内部维护 TTL 缓存的 `envSecretCache`。
- `metrics.go` 通过 OpenTelemetry 暴露 worker 计数 UpDownCounter 与生命周期/调度直方图，`Instruments` 可为 nil 作为 no-op。
- 依赖方向：Service → Workflow/Dialer/Informer/Syncer → store/workercache/k8s client；不反向依赖上层路由或 HTTP 层。
