main.go 是唯一的进程启动点，按固定顺序完成：解析 pflag → 初始化 serverboot（日志/追踪/指标）→ 连接 Redis Cluster（支持 IAM 认证与 TLS）→ 创建 Kubernetes clientset 与 ATE CRD informer → 构建 gRPC TransportCredentials（可选 pod-identity CA 校验客户端证书）→ 组装各子服务。

- controlapi.NewService 依赖 redisPersistence、workercache、多个 Lister、ateletDialer 和 k8s clientset，通过 WorkerPodInformer/AteletInformer 与 Pod 状态同步；其内部 syncer 将 WorkerPool 与 Pod 状态写入 Redis。
- actoridentity.New 依赖 JWT/X.509 签发配置与 Redis，为 atelet 提供短期 Actor 身份凭证。
- debugapi.NewService 仅依赖 Redis，暴露调试接口。

三个服务通过 ateapipb.Register*Server 注册到同一个 grpc.Server，共享统一的认证链（k8sjwt Bearer 验证 + ateinterceptors 最大超时 + 通用拦截器），并通过 serverboot.Readiness 暴露健康检查。关闭流程由 drainOnShutdown 统一处理 SIGTERM 后的优雅停机。
