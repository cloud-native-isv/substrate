以 `main.go` 为入口启动 gRPC 服务器并注册 `AteomHerder` 服务，三个核心 RPC 共享同一套错误处理、参数校验与 OpenTelemetry 埋点：`Run` 负责沙箱资产下载与 OCI bundle 生成后调用 ateom 的 `RunWorkload`；`Checkpoint` 按快照类型选择本地移动或并发 zstd 压缩上传至 GCS/S3，最后写入自描述 manifest；`Restore` 从对象存储或本地目录拉取快照，合并 golden snapshot 后调用 `RestoreWorkload`。模块内依赖方向清晰：`internal/ategcs` 抽象出 `ObjectStorage` 接口（GCS/S3 双实现），`oci.go` 生成 overlay 模式的 runtime spec，`volumes.go` 通过 `volume.VolumePluginWorkerPlane` 插件化挂载卷，`sandbox_assets.go` 管理内容寻址的沙箱二进制缓存，所有对 ateom 的调用均通过 `AteomDialer` 的 LRU Unix socket 连接池复用。
