### Actor
- 定义：Agent Substrate 中的基本工作单元，是从 ActorTemplate 派生的具体实例。Actor 具有完整的生命周期管理（Create/Resume/Suspend/Delete），可以在不同的 Worker 之间迁移，并支持状态保持。每个 Actor 通过 (atespace, name) 唯一标识，是 suspend/resume 操作的最小单位。
- 别名：actor实例、工作单元

### ActorTemplate
- 定义：Actor 的"类定义"，指定镜像、快照策略、沙箱类型等不可变配置。创建 ActorTemplate 时会触发 Golden Snapshot 的生成，用于快速启动新的 Actor 实例。模板定义了容器的 command/args、环境变量、卷挂载等，但不包含具体的实例状态。
- 别名：模板、类定义

### WorkerPool
- 定义：声明一组预热的 Worker Pod 容量，被 atecontroller 协调为 Kubernetes Deployment。WorkerPool 定义了物理计算能力，包括副本数、沙箱类型（gvisor/microvm）、节点选择器等。每个 Worker 同时只能托管一个 Actor，但多个 Actor 可以分时复用同一个 Worker。
- 别名：工作池、worker组

### Atespace
- 定义：Actor 的隔离边界和身份的第一部分，类似于命名空间但不是 Kubernetes namespace。Actor 通过 (atespace, name) 组合唯一标识，相同的 name 可以在不同的 atespace 中存在。Atespace 是全局作用域的，必须在创建 Actor 之前存在，且只有在空的时候才能删除。
- 别名：活动空间、隔离域

### Suspend/Resume
- 定义：Actor 的核心生命周期操作。Suspend 将运行中的 Actor 检查点（checkpoint）到快照并释放 Worker；Resume 从快照恢复 Actor 到可用的 Worker。这两个操作实现了 sub-second 级别的激活延迟，是 Agent Substrate 实现高密度复用的关键技术。Pause 是短期检查点，快照保留在节点上以便快速恢复。
- 别名：挂起/恢复、休眠/唤醒

### Request Parking
- 定义：atenet 路由器的核心特性，当目标 Actor 无法立即服务时（如 WorkerPool 饱和），路由器会"泊车"入站请求而不是立即返回 503。系统会重试 Resume 操作直到 Actor 可用或有界等待超时。这避免了瞬时容量不足导致的用户可见错误，提升了系统的弹性。
- 别名：请求泊车、请求排队

### Golden Snapshot
- 定义：ActorTemplate 创建时从临时"golden"启动生成的初始检查点，包含进程内存和 rootfs 增量。新创建的 Actor 默认从此共享快照恢复，提供快速启动能力。Golden Snapshot 总是 Full 类型的检查点，在 microvm 模式下还可以作为 fromData: Golden 的恢复源。
- 别名：黄金快照、初始快照

### Snapshot Scope
- 定义：定义 ActorTemplate 的 SnapshotsConfig 中包含的检查点范围。Full 范围捕获进程内存、rootfs 增量和 DurableDir 卷，用于热恢复；Data 范围仅捕获支持快照的卷内容（当前只有 DurableDir），用于低成本的数据持久化。onPause 和 onCommit 触发器分别控制 Pause 和 Suspend 时的快照范围。
- 别名：快照范围、检查点范围

### Uniform DNS Mesh
- 定义：Substrate 提供的统一 DNS 发现方案，每个 Actor 可通过固定格式的地址访问：<actor-name>.<atespace>.actors.resources.substrate.ate.dev。atenet 的 DNS 服务器解析这些地址到入口网关，实现位置透明的 Actor 发现。
- 别名：统一DNS网格、DNS发现

### DurableDir Volume
- 定义：一种特殊类型的卷，其内容通过 Data 快照范围保存并在 Suspend/Resume 间持久化。DurableDir 是 per-Actor 的应用数据表面，可以在多个容器中挂载。microvm 模板支持多个 DurableDir 卷（virtio-fs 子目录），而 gvisor 模板目前限制为单个卷。
- 别名：持久目录卷、数据卷

### ateom
- 定义：在每个 Worker Pod 内运行的协调器进程，代表 atelet 驱动沙箱运行时。ateom 解耦了物理 Pod 生命周期和沙箱化的代理进程，提供 gRPC 接口供 atelet 调用 RunWorkload、CheckpointWorkload、RestoreWorkload 等操作。根据沙箱类型分为 ateom-gvisor 和 ateom-microvm 两个版本。
- 别名：沙箱协调器、工作负载管理器

### atelet
- 定义：运行在每个节点上的 DaemonSet 形式的节点级监督者，作为"Herder"管理物理 Pod 池并与 Control Plane 通信。atelet 负责协调 snapshot 的上传下载、驱动 ateom 进程的生命周期、以及管理 Worker Pod 的状态。它是 Control Plane 和实际执行环境之间的桥梁。
- 别名：节点监督者、herder
