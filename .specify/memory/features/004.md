# Feature Detail: Request Routing & Parking

**Feature ID**: 004
**Name**: Request Routing & Parking
**Description**: Envoy-based traffic routing to actors with xDS control, actor DNS, and request parking during pool saturation.
**Status**: Implemented
**Created**: 2026-08-06
**Last Updated**: 2026-08-06

## Overview

atenet delivers the data plane: `atenet dns` provides actor name resolution
and `atenet router` runs an Envoy control plane (xDS) that routes inbound
traffic to the worker currently hosting each actor. When the worker pool is
oversubscribed, the router parks inbound requests until a worker frees up
instead of returning 503.

## Key Changes

1. Envoy xDS control plane (`cmd/atenet/internal/router/xds.go`).
2. External-process request handling (extproc_in / extproc_out).
3. Request parking (`router/parking.go`; docs/request-parking.md).
4. Actor DNS service (`atenet dns`).
5. Tunneling and pod networking (`internal/atunnel`, `internal/ateomnet`).

## Implementation Notes

- Envoy route timeout for long-running actor requests is configurable (recent
  upstream change, commit 4eedfef9).
- SPIFFE-based upstream identity verification in router config
  (`UpstreamSpiffePrefix`).
- E2E coverage: `internal/e2e/suites/networking`, `networkpolicy`, `parking`.

## Future Evolution Suggestions
