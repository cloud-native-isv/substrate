# Feature Detail: Actor Snapshot Persistence

**Feature ID**: 003
**Name**: Actor Snapshot Persistence
**Description**: Full-state snapshots (RAM + filesystem) streamed to GCS/S3 object storage, with tag-based snapshot management.
**Status**: Implemented
**Created**: 2026-08-06
**Last Updated**: 2026-08-06

## Overview

Suspend persists an actor's volatile RAM and filesystem state as a snapshot in
object storage; resume restores it on any worker. Snapshots are the mechanism
behind sub-second actor teleport and hibernation. The control plane exposes
GetActorSnapshot, ListActorSnapshots, TagActorSnapshot,
UpdateActorSnapshotTag, and DeleteActorSnapshotTag RPCs; atelet streams
snapshot data to/from storage with sparse zstd compression.

## Key Changes

1. Snapshot RPCs on the `Control` service (get/list/tag/update-tag/delete-tag).
2. GCS backend (`cmd/atelet/internal/ategcs/gcs.go`).
3. S3 backend (`cmd/atelet/internal/ategcs/s3.go`) — multi-cloud capable.
4. Sparse zstd snapshot compression (`sparsezstd`).
5. Kind/dev support via rustfs staging (`hack/microvm-assets/stage-to-rustfs.sh`).

## Implementation Notes

- Snapshot streaming is on the suspend/resume critical path; size and latency
  budgets matter.
- ateom checkpoint/restore produces the snapshot payload (features 006).
- UpdateActorSnapshotTag follows the substrate API guidelines (recent upstream
  change, commit aa9b7b82).

## Future Evolution Suggestions

- Incremental/delta snapshots for large-memory actors.
- Snapshot TTL and garbage-collection policies.
