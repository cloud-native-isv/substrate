# Feature Detail: Upstream Sync Automation

**Feature ID**: 016
**Name**: Upstream Sync Automation
**Description**: Scripted/CI-assisted upstream tracking: rebase xuanji onto main, detect upstream changes, and surface rebase conflicts early. (xuanji workflow feature)
**Status**: Draft
**Created**: 2026-08-06
**Last Updated**: 2026-08-06
**Type**: Non-functional (DFM)

## Overview

Constitution Principle I mandates the dual-branch workflow (main tracks
upstream, xuanji rebases onto it). Today that workflow is manual. This feature
adds automation so upstream syncs stay cheap and regular: tooling to fetch
upstream, fast-forward main, rebase xuanji, run the verify/test gates, and
report what changed upstream since the last sync.

## Latest Review

Bootstrapped from governance requirements during feature-registry
initialization (2026-08-06). No tooling exists yet.

## Key Changes

1. Upstream sync script (fetch upstream, ff main, rebase xuanji).
2. Pre-rebase gate: make verify + make test on the rebased tree.
3. Upstream change digest since last sync (commits, API/proto diffs).
4. Conflict reporting with ownership hints (upstream file vs custom feature).

## Implementation Notes

- Lives in hack/ or tools/ per repo layout rules; xuanji-branch-only tooling.
- Must never auto-force-push; human confirmation required for history
  rewriting (Constitution Principle XI).

## Future Evolution Suggestions

- Scheduled upstream-sync CI job producing a reviewable PR/branch.
- Drift monitor: alert when custom edits land in upstream-owned files.
