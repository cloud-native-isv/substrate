# Feature Detail: Actor Scheduling & Assignment

**Feature ID**: 002
**Name**: Actor Scheduling & Assignment
**Description**: Real-time assignment of actors to ready workers with caching, taking Kubernetes out of the critical path.
**Status**: Implemented
**Created**: 2026-08-06
**Last Updated**: 2026-08-06

## Overview

The scheduler maps a large set of actors onto a smaller set of ready worker
Pods in real time, bypassing the Kubernetes control plane in the critical path
to achieve low-latency resume/suspend. A worker cache tracks worker readiness
and occupancy to make assignment decisions fast.

## Latest Review

Bootstrapped from repo inventory during feature-registry initialization
(2026-08-06). No end-to-end feature review has been performed yet.

## Key Changes

1. Scheduling/assignment engine in `cmd/ateapi/internal/scheduling/`.
2. Worker cache (`cmd/ateapi/internal/scheduling/workercache/`).
3. ListWorkers API for pool visibility.
4. Coordination with atelet for on-node actor placement.

## Implementation Notes

- Assignment latency is the system's key metric; changes must not add
  synchronous Kubernetes API calls to the resume path.
- Worker pool size/scale is managed via the WorkerPool CRD (feature 005).

## Future Evolution Suggestions

- Affinity/anti-affinity hints for actor placement.
- Predictive pre-warming of workers based on resume patterns.
