# Feature Detail: Multi-Actor Worker Pod

**Feature ID**: 020
**Name**: Multi-Actor Worker Pod
**Description**: Break the upstream "1 worker pod = 1 active actor" model — one worker pod concurrently hosts N active agent sandboxes of a single digital employee (spatial multiplexing), the prerequisite for a shared MCP capability backend. (xuanji custom feature)
**Status**: Draft
**Created**: 2026-09-20
**Last Updated**: 2026-09-20

## Overview

Upstream substrate multiplexes many actors onto fewer workers **temporally** — via
suspend/resume, an idle actor is swapped out and the worker serves the next (at any
instant ~1 active actor per worker). Xuanji adds **spatial** multiplexing: one worker pod
= one digital employee's **S trust domain**, concurrently hosting **N active agent
sandboxes** plus their **shared MCP capability backend** (feature 019). This is a key
fork improvement over upstream — a digital employee naturally runs parallel sub-tasks /
multiple agents, and a 1:1 model would force each sub-task to occupy its own worker pod
(wasting the warm pool, lengthening cold start) and make "shared by these agents"
meaningless.

Intra-pod isolation **rides on wasm per-context fuel/memory limits** (ADR 0003 D2), not
container-per-actor — consistent with the two-tier model's "actor is not isolated by
container" (two-tier-sandbox-model.md §1). Spatial multiplexing coexists with the
existing temporal multiplexing (N:1 is a layer on top of suspend/resume).

## Key Changes

1. **F9 scheduler/store N:1 binding** — ateapi allows N actors concurrently bound to one
   worker (actor→worker N:1 instead of 1:1), consuming ateom's `SetWorkerCapacity(actors=N)`.
2. **WorkerPool capacity model 1→N** + per-actor resource accounting; coexists with the
   existing suspend/resume temporal multiplexing.
3. **Intra-pod contention bounds (residual tension R4)** — per-actor wasm fuel/mem limits
   (ADR 0003 D2) + pod-level sizing/quota so a noisy actor cannot starve siblings.
4. **Reconcile pool models** — "one digital employee = one worker pod" (panorama §2) with
   the existing "per-tenant pool" warm-pool model (two-tier-sandbox-model.md §1).

## Implementation Notes

- **Division of labor**: fork/substrate = F9 (scheduling/capacity N:1); sandbox = S12
  (ateom-wasmd `ActiveWorkload` multi-instance + `SetWorkerCapacity(actors=N)`). See
  sandbox `two-tier-sandbox-layer-design.md` §6 / S12.
- **Updates the density model** in two-tier-sandbox-model.md §1: "每 RUNNING actor 一个
  worker pod" → "每数字员工一个 worker pod、内含多并发 agent 沙箱" (a pointer note is
  already added there).
- **Prerequisite for feature 019** (MCP capability backend "shared by these agents") —
  sequence F9/S12 before F10/F11/S10.
- Aligns with substrate's "many actors → fewer workers" intent (higher density); it is an
  extension, not a departure.

## Future Evolution Suggestions

- Per-actor QoS / fair-share scheduling within a worker pod.
- Dynamic N — scale concurrent actors per worker by load / employee tier.
