# Feature Detail: Wasm Sandbox Runtime

**Feature ID**: 014
**Name**: Wasm Sandbox Runtime
**Description**: WebAssembly-based sandbox backend as a lightweight alternative to gVisor/microVM, plugged into the atelet/ateom lifecycle contract. (xuanji custom feature)
**Status**: Draft
**Created**: 2026-08-06
**Last Updated**: 2026-09-20

## Overview

Xuanji-branch custom feature: add a Wasm-based sandbox type so actors can run
as WebAssembly workloads — faster cold start and higher density than container
or microVM sandboxes for compatible workloads. Must integrate with the existing
multi-sandbox architecture (feature 006): same lifecycle operations, snapshot
behavior where feasible, and SandboxConfig wiring. No product code exists yet
(verified 2026-08-06: repo-wide search found no Wasm implementation).

## Latest Review

Bootstrapped from user-stated roadmap during feature-registry initialization
(2026-08-06). Design not started.

**2026-09-20 (design now authored)**: this feature is the **execution body of the Agent
trust domain** in the four-trust-domain panorama (`docs/concepts/trust-domain-panorama.md`).
Its design is now authoritative across: [ADR 0002](../../../docs/decisions/0002-two-tier-supervisor-worker-sandbox.md)
(two-tier model — wasm sandbox = the actor execution body nested in the worker pod),
[ADR 0005](../../../docs/decisions/0005-rust-agent-execution-body.md) (execution-body form
pivot: **Rust agent + standard WASI SDK + custom host functions**, security-first;
CPython demoted to a `python_exec` tool), and [ADR 0003](../../../docs/decisions/0003-wasm-host-function-security.md)
(host-function security = the S↔Agent boundary). Native-capability extension beyond the
wasm surface is split out to feature **019 (MCP Native Capability Backend)**; the
multi-actor-per-worker hosting model is split out to **020 (Multi-Actor Worker Pod)**.
Status stays Draft (no committed capability); the design gap that blocked planning is now closed.

## Key Changes

1. Choose Wasm runtime (wasmtime/wasmedge/WAMR) and capability/WASI model.
2. New ateom-wasm herder implementing the atelet/ateom lifecycle contract.
3. SandboxConfig profile for Wasm actors; ActorTemplate support.
4. Snapshot/restore strategy for Wasm instances (or documented limitations).
5. E2E suite for Wasm actors (lifecycle, routing, identity).

## Implementation Notes

- xuanji-branch-only feature (Stage 2 fusion work); separability is preferred but not
  required — upstream code may be modified, with each modified file registered in
  `xuanji.md` (Constitution Principle I).
- Security posture must match or exceed gVisor isolation expectations for the
  supported workload class; document trust boundaries in the design.
- **Execution body = the Agent trust domain** (panorama §1): the agent is *less trusted
  than its owner* (an LLM can be steered by injected content), so credentials/identity stay
  in the S layer (ateom) and never enter wasm (ADR 0003 D6); the agent is a capability-bounded
  delegate. Execution-body form = Rust agent + standard WASI SDK (ADR 0005), not CPython-as-main.
- Design authority (supersedes the earlier `docs/wasm-sandbox/overview.md` target):
  ADR 0002 (two-tier) + ADR 0005 (execution body) + ADR 0003 (host-function security) +
  `docs/concepts/trust-domain-panorama.md` (four-trust-domain frame). Sandbox-side build-out
  = sandbox repo S1/S4/S5 (`two-tier-sandbox-layer-design.md`).
