# Feature Detail: Control Plane State Store

**Feature ID**: 010
**Name**: Control Plane State Store
**Description**: Redis/Valkey-backed control-plane state store for actor and scheduling metadata, with dev-friendly alternatives for kind.
**Status**: Implemented
**Created**: 2026-08-06
**Last Updated**: 2026-08-06

## Overview

The control plane persists actor, assignment, and snapshot metadata in a
Redis-compatible store (Valkey in production manifests; miniredis in tests).
The store sits behind the ateapi scheduling layer and is flushable via
`kubectl ate admin debug redis flush` for development resets.

## Latest Review

Bootstrapped from repo inventory during feature-registry initialization
(2026-08-06). No end-to-end feature review has been performed yet.

## Key Changes

1. Redis/Valkey store backend (`cmd/ateapi/internal/store/ateredis/`).
2. Valkey deployment manifest (`manifests/ate-install/valkey.yaml`).
3. miniredis-based test doubles.
4. Admin debug flush command in kubectl-ate.

## Implementation Notes

- go-redis v9 client; store interface allows alternate backends.
- State store availability directly affects control-plane liveness — keep
  operations bounded and idempotent.

## Future Evolution Suggestions

- Store backend abstraction for non-Redis deployments.
- HA/sentinel topology guidance for production Valkey.
