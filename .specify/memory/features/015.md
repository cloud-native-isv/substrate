# Feature Detail: Workload Security Hardening

**Feature ID**: 015
**Name**: Workload Security Hardening
**Description**: Close early-stage security gaps: authorization policies, dependency scanning/SBOM, and threat-model-driven hardening beyond gVisor isolation.
**Status**: Draft
**Created**: 2026-08-06
**Last Updated**: 2026-08-06
**Type**: Non-functional (DFSec)

## Overview

The project's own documentation states the security story is early and many
features are missing (agents.md; docs/threat-model.md). Identity exists
(feature 007), but authorization, supply-chain scanning, and systematic
hardening are gaps. This feature tracks closing them in priority order.

## Latest Review

Bootstrapped from DFX gap analysis during feature-registry initialization
(2026-08-06). No dedicated security review performed yet.

## Key Changes

1. Authorization model for Control API callers (who may manage which atespaces).
2. Dependency scanning + SBOM generation in CI.
3. Threat-model-driven hardening backlog (docs/threat-model.md as anchor).
4. Secrets handling review for manifests and setup tooling.

## Implementation Notes

- gVisor remains the isolation boundary; this feature hardens everything
  around it.
- Constitution requires the security section of agents.md to stay current as
  capabilities land.

## Future Evolution Suggestions

- Per-atespace network egress policies as a first-class API.
- Audit logging for all control-plane mutations.
