# Feature Detail: Workload Security Hardening

**Feature ID**: 015
**Name**: Workload Security Hardening
**Description**: Close early-stage security gaps: authorization policies, dependency scanning/SBOM, and threat-model-driven hardening beyond gVisor isolation.
**Status**: Draft
**Created**: 2026-08-06
**Last Updated**: 2026-09-20
**Type**: Non-functional (DFSec)

## Overview

The project's own documentation states the security story is early and many
features are missing (agents.md; docs/threat-model.md). Identity exists
(feature 007), but authorization, supply-chain scanning, and systematic
hardening are gaps. This feature tracks closing them in priority order.

## Latest Review

Bootstrapped from DFX gap analysis during feature-registry initialization
(2026-08-06). No dedicated security review performed yet.

**2026-09-20 (security design now authored)**: the workload-security story is now specified
by a coherent ADR set under the **four-trust-domain panorama** (`docs/concepts/trust-domain-panorama.md`,
I/P/S/Agent) — this feature is the **umbrella for S-layer hardening + the cross-domain
audit/allowlist principle**: [ADR 0003](../../../docs/decisions/0003-wasm-host-function-security.md)
(host-function security + three-ring audit = the S↔Agent boundary), [ADR 0004](../../../docs/decisions/0004-runc-worker-pod-hardening.md)
(runc worker-pod hardening = outer containment + runc admission), [ADR 0006](../../../docs/decisions/0006-security-spectrum-model.md)
(three-slider security spectrum), [ADR 0007](../../../docs/decisions/0007-mcp-native-capability-backend.md)
(MCP capability backend security). The panorama's universal principle — **every cross-trust-domain
operation carries allowlist + audit** (F12) — generalizes ADR 0003 D1/D7 from the wasm boundary
to all crossings (I↔P / P↔S / S↔S / S↔Agent / S↔MCP). Status stays Draft.

## Key Changes

1. Authorization model for Control API callers (who may manage which atespaces).
2. Dependency scanning + SBOM generation in CI.
3. Threat-model-driven hardening backlog (docs/threat-model.md as anchor).
4. Secrets handling review for manifests and setup tooling.
5. **runc worker-pod L2/L3/L4 hardening (ADR 0004)** — `allowPrivilegeEscalation:false`,
   pinned seccomp, `readOnlyRootFilesystem`, `hostUsers:false` (userns), hostPath narrowing;
   dedicated nodes + east-west-default-deny NetworkPolicy; Ring 2 mandatory for the runc pool;
   **runc admission = D8 gates ∧ L2 ∧ L3 ∧ Ring 2**.
6. **F12 cross-domain audit + allowlist unification (panorama §5)** — generalize ADR 0003
   D1 (allowlist) + D7 (three-ring audit) to *every* trust-domain crossing (I↔P / P↔S /
   S↔S / S↔Agent / S↔MCP); unified audit event carries `src_domain`/`dst_domain`; S↔S
   default-deny except via the shared MCP pool with per-tenant isolation.
7. **Three-slider security spectrum as policy (ADR 0006)** — per-tenant-pool declaration of
   ① runtime (runc↔rund) × ② execution body (cpython↔rust) × ③ tool surface, with
   cross-dimension compensation invariants + an admission webhook generalizing ADR 0004 D6.
