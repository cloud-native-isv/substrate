# Ask, Record, Repeat(问一次、记下来、说三遍)

知识生命周期的单一真源。三条理念合并为**一个闭环**,不是三条并列的规矩:

> **获取**(问,而不是猜)→ **保留**(记下来,并从一个实例推出这一类)→ **保活**(重复到它会抵达下一回合的地方)。

三环缺一,闭环就断:只问不记 → 同一个问题问第二遍;只记不重复 → 记下来的东西躺在没人读的文件里;只重复不问 → 把猜来的前提到处复制。

本文档由指令文件的 `## Ask, Record, Repeat` 章节以指针引用;该章节只承载摘要,细则归此处。

---

## 为什么是"理念"而不是一条硬规则

硬规则可以被机械判定(计数、退出码、结构断言),这三条不能——"这个问题是否吃重"、"这条答案该记在哪"、"这条规矩值不值得再占一个表面"都是判断。所以它们以理念形态存在:约束的是**倾向与默认动作**,而不是可判定的输出。判断标准给到可操作的程度,但不假装可机械裁决。

与既有机制的关系(引用,不复述):

- 输入合理性的升级规则见指令文件的 `## Fact, Correctness & Logic Checks (Input Sanity)`。
- "需求不清本身就是高风险信号"见 `shared/guidelines/task-complexity-rubric.md`。
- 事实该记在哪个文件,由 `shared/guidelines/one-source-of-truth.md` 裁定。
- 术语与同音易混词的记录位是项目词汇表。

## 1. Ask —— 问好过于猜

**规范**:当一个**吃重**的事实未知或有歧义时,提问;不要猜。

"吃重"的判据(满足任一即吃重):

- 影响正确性、安全、数据丢失,或触发大范围重构;
- 有多个都说得通的答案,且选错要返工;
- 是不可逆或难以回退的动作的前置条件;
- 答案会决定后续一批动作的方向(而不只是这一步)。

**同样重要的是不该问的时候**——提问是有成本的,滥用会把用户的注意力耗在仪式上:

- 能从仓库、代码、既有文档里查到的,**先查**;查不到再问。
- 只有一个合理答案、且改动可逆的,直接做并在报告里说明所采用的解读。
- 一次把相关问题**成组问完**,不要挤牙膏式地一问一答。
- 问题里带上**自己的推荐**与取舍,让用户是在裁决而不是在替你做调研。

**成本不对称**是这条理念的全部理由:一个问题很便宜,一个错误前提很贵——它会在下游被当成事实反复引用,越晚发现越贵。猜错最贵的地方不是错本身,而是**错得很安静**。

## 2. Record —— 好记性不如烂笔头

**规范**:从用户那里得到的答案 MUST 被写下来,写在**下一回合会读到**的地方。

"下一回合会读到"是这条的判据,不是修辞。只存在于当前对话上下文里的记录,会随会话结束而消失,等于没记。落点按事实的种类选:

| 得到的答案属于 | 落点 |
|---|---|
| 某个概念/术语的含义、同音易混词 | 项目词汇表(用户条目为权威) |
| 某类行为的规范判据 | 该主题的 `shared/guidelines/` 真源文档 |
| 某个项目特定的坑、环境怪癖 | 指令文件的项目经验章节 |
| 某个特性的裁定与澄清 | 该特性目录下对应阶段的产物 |
| 一次性的偏好、本轮的范围裁定 | 项目记忆层 |

落点的**归属裁定**归 `shared/guidelines/one-source-of-truth.md`;本表只回答"这类答案通常去哪",不重复其规则。

**举一反三、触类旁通**——这是记录环节最容易做错的一半:

- 记下**规则**,不是实例。用户纠正了一个个例,要提炼出它所属的那一类,把类记下来;只记个例,下次遇到同类仍会犯。
- 一次纠正值多条:问"这个错误还能在哪里出现?",把同类位置一并处理,而不是等它们逐个暴露。
- 记**为什么**,不只记**是什么**。带理由的规则能被正确外推到没预料到的情形;不带理由的规则只会在字面匹配时生效。
- 反向也成立:从用户的一个答案里能推出的其他结论,应当当时就推出来并一并确认或记录,而不是留到下一次撞墙。

**一条好记录的检验标准**:同一个问题不需要问第二遍。如果发现自己第二次问同一件事,那不是记性差,是上一次没记对地方。

## 3. Repeat —— 重要的事情说三遍

**规范**:一条规矩**只在一个地方出现过**,等于它不存在——因为没有任何机制保证读者会去那个地方。

这不是修辞,是可观测的失效模式:一条规则被正确写下、归属清晰、措辞无误,却因为没有从"每个回合都会读到的表面"可达,于是执行者径直撞上它所禁止的那个坑。**归属正确 ≠ 可达**。单一真源解决的是"哪个版本算数",不解决"谁会读到"。

**重复次数是重要度的信号**,两个方向都成立:

- 项目把一条规矩铺到越多表面,说明它越重要——这是刻意投入,不是冗余。
- 反过来,一条你**反复重新推导**的规矩,是一条还缺表面的规矩。第二次靠自己想起来时,就该给它加一层可达性,而不是庆幸自己记住了。

**house 模式(三层表面)**:真源文档(细则)→ 指令文件的常驻章节(摘要 + 指针)→ 契约测试(防漂移)。第三层是关键:没有守卫的重复会各自漂移,最后三处说法不一,比重复之前更糟。

### 与 Principle XIV 的裁定:指针形态可重复,内容形态仍禁止

"说三遍"与单一真源(引用不复述、副本即漂移)存在张力。裁定如下,写死在此以免被当成复制内容的许可证:

| 形态 | 是否允许 | 判据 |
|---|---|---|
| **指针形态的重复** | ✅ 允许,且被鼓励 | 每个表面只放**短规范提醒 + 指向 owner 的路径**;细节一律不搬 |
| **内容形态的重复** | ❌ 禁止 | 复述 owner 的表格、阈值字面量、枚举清单、判据正文 |

机械判别法:**改这个事实需要编辑几个文件?** 只需改 owner 一个 → 是指针形态,合规。需要同时改多处 → 是内容形态,已经违约,修复方向是把副本改回引用(不是把措辞改到一致)。

短提醒与复述的分界:提醒只说"有这么一条规矩、它归谁管",读者若要据此行动**必须**去打开 owner;复述则让读者不必打开 owner 就能行动。前者是路标,后者是抄本。

## 这个闭环关掉的三种失效

| 失效模式 | 由哪一环关掉 | 安静程度 |
|---|---|---|
| 按错误前提行动,并在下游被反复引用 | Ask | 最安静——前提错时,后续每一步都"看起来对" |
| 同一个问题问第二遍;只学会个例学不会类 | Record | 中等——用户会注意到被重复提问 |
| 规则存在但不可达,执行者撞上它所禁止的坑 | Repeat | 安静——归属清晰,所以没人怀疑它没生效 |

三者共同的性质是**安静**:都不会报错,都表现为"下游某处莫名其妙地错了"。这正是把它们写成理念而不是等测试去抓的原因。

## 维护义务

- 给一条规矩新增表面时,MUST 同批加守卫(契约测试或既有扫描),否则新增的是未来漂移点而不是可达性。
- 发现自己在**第二次**推导同一条规矩:当轮就给它补一层表面,并把这次重复记为该规矩重要度的证据。
- 发现某处是**内容形态**的重复:按 `shared/guidelines/one-source-of-truth.md` 的修复方向,把副本改成引用,不要把措辞改到一致。
- 用户给出的答案若与既有文档冲突:先按 Ask 澄清归属,再落 Record;不要在两个地方各留一个版本。
