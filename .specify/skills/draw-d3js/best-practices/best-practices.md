# draw-d3js 最佳实践（Best Practices）

> 从 viz-skill-arena 竞技 cycle（Substrate 架构图，2026-08-07）的 R1 评审建议与重绘改进中沉淀。R1 评审明确认可 d3js 状态机图范式，并指出数据组织与可复现性改进方向。配套陷阱见 [pitfalls.md](pitfalls.md)。

## 1. 状态机图范式（评审认可的参考范式，固化）

R1 评审明确建议：*"状态机图质量高（侧栏状态语义 + 生命周期动词 + 动画虚线 + 图例 + tooltip），可作为 draw-d3js 状态机类图的参考范式固化进技能 references"*。范式要素：

- 侧栏展示状态语义说明（状态名 + 含义），图主体只画迁移；
- 生命周期动词（Suspend/Pause/Resume）标注在迁移边上；
- 关键迁移用动画虚线（如恢复路径），普通路径实线；
- 图例色块说明状态类别；节点/边 tooltip 补充细节。

## 2. 数据抽离为独立文件 + 本地 vendor d3

R1：*"数据全部内嵌单 HTML，维护性差，建议抽离为独立 JS/JSON 数据文件并本地 vendor d3（CDN 依赖影响离线可复现）"*。规范：

- 数据外置为独立 `data-*.js` 文件（nodes/links/rels 分离），HTML 只做渲染壳；
- 本地 vendor `d3.v7.min.js`，不依赖 CDN——离线可复现。

## 3. 力导向图固定布局（可复现）

R1：*"力导向图初始布局随机（无 seed/预设坐标），多次打开布局不同"*。规范：

- 提供固定布局预设或记录初始坐标（如手工布置的节点坐标数组）；
- 或按子系统分组做力导向（组内聚、组间疏），保证每次打开结构一致。

## 4. 边标签默认隐藏，悬停显示

R1：*"33 条边标签全部常显（10px），与节点/连线密集重叠"*。规范：

- 边标签默认隐藏，`mouseover` 时显示；
- 或按 type 分组着色 + 精简标签文本。

## 5. 基础设施节点独立分组 + 图例色点

R1：*"存储类节点（Valkey/CRD/GCS）被归入具体子系统分组，语义上它们是基础设施；建议独立分组并配独立图例色"*。规范：

- 存储/基础设施类节点独立成组，不混入业务子系统；
- 图例带色点色块（不只右上角文字），分组含义一目了然。

## 6. 热力图长标签控制

R1：*"热力图列头 -32° 旋转长标签与 42px 单元格宽度接近极限"*。规范：

- 列头长名缩短为展示名（如 ate-api-server → API Server），tooltip 显示全名；
- 或增大列头区宽度/换行，避免旋转标签极限挤压。

## 7. 悬停明确方向语义

热力图中行=依赖方/列=被依赖方的约定易混淆（R1：*"「dns→router 流量拦截」方向与行/列约定易混淆"*）。规范：悬停时明确显示方向文字（"X → Y：流量"），或默认可见方向说明。

## 8. 复现附录随图交付

R1：*"HTML 内缺少显式的「重新生成」说明（渲染命令/数据修改指引仅存在于注释），建议像 mermaid/plantuml 一样增加复现附录，说明 data-*.js 的维护方式"*。规范：HTML 输出附复现附录（可见的折叠页脚 + 文件头注释块）：打开即渲染、无构建步骤；data-*.js 各数组对应图面哪部分；修改后刷新即重渲染。参考 [template.html](../assets/template.html) 样板。

## 9. 矩阵强度评分标尺

R1：*"依赖矩阵的强度值（0-4）为主观赋值，建议在 notes 或数据文件中给出评分标尺，提升可复现性与评审可解释性"*。规范：数据文件头 + 图注中定义强度语义（如 4=强同步依赖 / 1=弱关联）；无标尺的主观值不可评审、不可复现。

## 10. 边标签「常显」开关

R1：*"架构图边标签默认悬停显示，静态打印/截图时信息缺失；可仿照 echarts 增加「常显边标签」开关，便于文档嵌入"*。规范：默认悬停、提供可切换的「常显边标签」开关（checkbox/button），保证静态嵌入文档时标签可读；不得把标签锁死在悬停态。

## 11. 推断路径显式标注

R1：*"状态机中 FAILED→SUSPENDED 人工介入恢复属推断补充，建议在图内显式标注「描述未定义，推断路径」，避免读者误读为源描述"*。规范：作者推断的迁移/状态（源描述未定义）用区别样式 + 「描述未定义，推断路径」标注；恢复路径在图例/侧栏显式列出（如 冷启重建: FAILED → SUSPENDED → BOOTING），不只藏在 tooltip desc。

## 12. 数据溯源标注

R1：*"与 echarts/plantuml 一样采用 per-tenant Etcd 状态层，与 mermaid 的 Valkey CAS 叙事冲突，建议在 data 文件/annotation 中标注所依据的架构描述版本与日期"*。规范（取通用原则）：数据文件头标注架构描述版本与日期（如 `// 依据: docs/architecture.md v2.3 (2026-08-01)`），图与源可对照审计，叙事漂移可追溯。

## 13. 手工坐标栅格规则 + 校验

R1：*"固定手绘坐标可复现性好，但节点增删易重叠；建议在数据文件头记录坐标分区栅格规则，或附带坐标校验脚本（检测节点重叠/面板越界）"*。规范：数据文件头记录分区/栅格规则；渲染前跑重叠/越界校验（参考 d3js-guide 的 validateCoords 片段）。

## 14. 跨面板锚点 + 正交路由

R1：*"架构图中跨面板长连线较多，建议统一面板间锚点出口/入口，或对跨面板边做正交化路由"*。规范：面板边界设统一出口/入口锚点；跨面板边用正交（elbow）路由，避免长对角线切穿无关面板。

## 15. 导出能力

R1：*"交互已很丰富，但缺导出能力；建议增加「导出 SVG/PNG」按钮（SVG 序列化 + Canvas 转换），便于嵌入报告文档"*。规范：面向文档嵌入的图提供导出按钮；导出为静态快照（hover/tooltip 状态不包含），外部样式/字体需内联（参考 d3js-guide 的 exportSVG/exportPNG）。
