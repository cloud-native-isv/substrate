# Step 1: 语义解析 + 吃透上下文

> **适用范围**：draw-diagram 委派时语义/几何以 **SDS 为准**（见 [../sds-realization.md](../sds-realization.md)），本指南只用于**直接调用（无 SDS）**——此时本技能临时承担语义角色，产出需声明假设。

## 目标

把用户的自然语言诉求变成明确的绘图意图清单：画什么、给谁看、突出什么。

## 操作

1. **解析意图**：从用户输入提取——图表主题、元素清单（组件/角色/步骤）、关系（调用/依赖/流转/层级）、期望风格（手绘程度、配色倾向）。
2. **吃透上下文**：当输入是文档/代码/会议纪要时，先产出**带出处的上下文摘要**：
   - 组件/角色清单（名称 + 一句话职责）
   - 关系清单（谁 → 谁，什么语义）
   - 核心流程/关键决策
   - 后续绘图与自检都对着这份摘要，保证整体正确、不臆造。
3. **确认提问**（`AskUserQuestion`，最多一轮 ≤4 问），仅在以下情况：
   - 元素/关系有歧义或缺口（摘要里出现"不确定"）
   - 用户点名多类图但未说明侧重
   - 交付形态不明（单图/图集、是否要可编辑源文件）
   - 已经很清楚就不问，直接进 Step 2。

## 产出

- 上下文摘要（内部使用，不必交付给用户）
- 一句话绘图目标：`为 <对象> 画一张 <类型> 图，突出 <核心点>`
