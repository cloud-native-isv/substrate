# draw-echarts 最佳实践（Best Practices）

> 从 viz-skill-arena 竞技 cycle（Substrate 架构图，2026-08-07）的 R1 评审建议与重绘改进中沉淀。ECharts 是数据可视化引擎，用于架构类需求时的取舍与纪律在此固化。配套陷阱见 [pitfalls.md](pitfalls.md)。

## 1. 数据/配置外置为独立文件（可维护性）

图数据与配置不要全部内嵌进单个 HTML（R1：*"图数据与配置全部内嵌 JS 单文件，重生成需手工编辑"*）。规范：

- 数据外置为独立 `*.config.js` / `*.config.json` 文件，HTML 只负责加载与渲染；
- 重绘/改图只改数据文件，不动渲染壳——重绘版引入 config.json 后评审认可，应固化为默认结构。

## 2. 状态机 [*] 起止节点显示文字

`[*]` 伪节点默认渲染为空圆无法辨识（R1 实测：*"label formatter 对 category 3 返回空串，视觉上无法辨识"*）。规范：

- 起止节点显示 `[*]` 或「开始/结束」文字；
- 节点框按状态类别着色（稳态/迁移/异常态），与图例一一对应，不要只给边着色。

## 3. 未定义态显式标注（保真纪律）

源描述中未定义的语义（如某状态下架构未定义）要显式标注「未定义/不含」，绝不臆造。R1 认可：*"状态机与资源分层图语义准确（明确标注「PAUSED 态架构未定义故不含」），保真纪律好"*——此惯例应固化为模板默认行为。

## 4. 边标签默认隐藏，悬停显示

力导向/关系图边标签全部常显会在密集区互相遮挡（R1：*"edgeLabel 在密集区相互遮挡"*）。规范：

- 边标签默认不显示，`emphasis`（悬停）时显示；
- 或启用 `labelLayout` 避让；
- 或按边类型分组着色 + 精简标签文本。

## 5. 架构类需求：固定布局或分区背景，力导向仅作关系视图

力导向图作为「组件架构图」表达适切性有限（R1：*"节点重叠、无子系统边界与从属层次"*）。规范：

- 组件/架构视角改用固定布局（graph 带分区背景或树形/矩形树）表达子系统边界与层次；
- 力导向图仅用于「关系视图」，并在标题中明确标注，避免被误读为架构图。

## 6. 锁定版本 + 本地回退（可复现）

HTML 依赖 CDN echarts@5，离线不可渲染（R1 点名）。规范：

- 锁定具体版本号（如 echarts@5.4.3）；
- 提供本地回退：内嵌最小构建或 vendored 副本，保证离线可复现。

## 7. 交付清单逐项核对，缺图明确说明

任务要求多类图时（如组件/部署/序列/状态机/资源模型），逐项核对交付清单。确实无法用 ECharts 表达的图型（如部署架构），要么补一张视图，要么在文档中**明确说明以关系图替代的取舍**（R1：*"部署架构图缺失（仅以关系图近似覆盖），建议补部署视图或明确说明取舍"*）。

## 8. 标题/图例/脚注去重

图内 title 与容器标题重复、图例与说明冗余会浪费图面（R1 建议精简）。规范：每类信息只出现一次。

## 9. 离线交付：本地副本必须真实存在（vendor 非空）

引用 `vendor/echarts.min.js` 却未实际下载（vendor/ 空目录 + CDN document.write 回退），离线打开全空白（R1 两次点名：*"vendor/echarts.min.js 未下载"*、*"离线打开 HTML 无法渲染"*）。规范：

- 交付前把锁定版本的 `echarts.min.js` 真实放入 vendor/（`scripts/vendor-echarts.sh <dir>` 下载并校验非空/版本标记/JS 语法）；
- 加载器禁用 `document.write`（阻塞、废弃、CSP 不友好），改用本地优先 + CDN `onerror` 动态回退（见 SKILL.md Step 4 模板）；
- 交付前跑 `node scripts/verify-deliverable.mjs <html>` 做结构性检查。

## 10. 交付附静态渲染产物（PNG/SVG 渲染证明）

仅 HTML + 依赖 CDN 时，评审离线无法核验实际效果（R1：*"无任何静态渲染产物（PNG/SVG），评审无法离线核验"*）。规范：

- 交付时用 toolbox 保存图片 / `chart.getDataURL()` / headless 截图导出 PNG/SVG，随 HTML 一并输出；
- 本地打开验证（断网重开）确认 canvas 非空白，再交付。

## 11. 推断边与源描述边可视化区分（补全边界）

「RUNNING 直出 DELETE」「CRASHED 人工 Delete」等源描述未详述、按模型补全的语义，脚注虽标注但不够醒目（R1 点名）。规范：

- 推断/补全边用**虚线灰边**，源描述边用**实线**，人工介入边用**红色虚线**，并显式画出（不能只在 desc/工具提示里）；
- 图内图例或 `title.subtext` 说明「虚线=补全/人工介入」，脚注不足以承载该信息。

## 12. 配置单一权威格式 + 生成脚本（防漂移）

config.js 与 config.json 双副本手工同步会漂移（R1：*"双副本手工同步有漂移风险"*）。规范：

- 以 `*.config.json` 为唯一权威，`*.config.js` 由 `node scripts/sync-config.mjs <file>.config.json` 生成；
- 交付前用 `sync-config.mjs --check` 或 `verify-deliverable.mjs` 校验两文件一致；
- 复现说明中写入生成命令。

## 13. 多图共用设计令牌（design tokens）

三图共用暗色主题但色板分散在各 config（R1：*"色板分散…可抽成统一 design-token 字段"*）。规范：

- 多图交付定义一个共享 `window.DESIGN_TOKENS`（调色板/主题/背景/字体/边样式语义），各 config 引用它；
- 单一修改点保证跨图视觉一致。

## 14. 固定布局坐标纪律（栅格规则 + 校验）

手写固定坐标的 graph 节点/分区随维护易重叠（R1：*"18 节点在 900px 画布上较密"*、*"手写固定坐标长期维护易重叠"*）。规范：

- config `meta` 记录画布尺寸（canvasWidth/Height）与栅格规则；
- 交付前跑 `node scripts/check-layout.mjs <config>`（越界/重叠/分区越界检查）。

## 15. 校正/仲裁需附依据（可复核）

资源分层图「保真校正」（CRD→per-tenant Etcd）与任务简述/mermaid 解读冲突时，单向校正不可仲裁（R1 点名）。规范：

- 源描述含新旧两段时，图内同时呈现并标注时间点，而非单向校正；
- 分区标题用「已迁移/演进」等演进词，图例区分「活跃关系/演进关系」而非裸「旧」；
- 交付说明附校正依据（架构描述出处），供仲裁与复现复核。
