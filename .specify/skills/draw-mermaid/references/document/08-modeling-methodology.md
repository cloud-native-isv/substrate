# 建模方法论（08）

## 1. 面向对象设计原则

| 原则 | 含义 | 图上的体现 |
|------|------|-----------|
| SRP 单一职责 | 一个类一个职责 | 类图：类职责内聚 |
| OCP 开闭 | 对扩展开放、对修改关闭 | 类图：抽象类/接口 + 实现 |
| LSP 里氏替换 | 子类可替换父类 | 类图：泛化正确性 |
| ISP 接口隔离 | 接口小而专 | 类图：接口拆分 |
| DIP 依赖倒置 | 依赖抽象不依赖实现 | 类图：依赖指向接口 |

## 2. 设计流程（图驱动）

1. **需求 → 用例**：范围界定（用例图近似）；
2. **用例 → 场景**：时序图描述交互；
3. **场景 → 类**：职责分配（GRASP）→ 类图；
4. **类 → 行为**：状态机图定义生命周期；
5. **验证**：图集交叉检查（类图 vs 时序图一致）。

## 3. SOLID 在类图中的检验

- 每个类的职责一眼可见（SRP）；
- 高层模块只依赖接口（DIP）——依赖箭头指向抽象；
- 继承层级 ≤3 层（LSP 可维护性）。

## 4. 架构方法论

- **C4 分层**：上下文 → 容器 → 组件 → 部署（document/10）；
- **分层架构**：展示/应用/领域/基础设施（依赖单向）；
- **端口-适配器**：领域层定义接口，基础设施实现（`..|>`）。

## 5. 建模纪律

- 图服务于决策：不画没人看的图；
- 模型与代码同步：代码变了图必须更新（源文件可 diff）；
- 上下文摘要先行：不臆造（diagram-principles §4.1）。
