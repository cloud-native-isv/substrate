# 状态机图理论（06）

## 1. 状态机本质

- 描述**单个对象**在其生命周期中的状态与转换；
- 状态 = 对象满足某条件/等待某事件的情形（名词短语）；
- 转换 = 事件触发下的状态迁移（`事件[守卫]/动作`）。

## 2. 元素

| 元素 | 语义 | Mermaid |
|------|------|---------|
| 初始状态 | 生命周期起点 | `[*]` |
| 状态 | 对象所处情形 | `状态名` |
| 终态 | 生命周期终点 | `[*]` |
| 转换 | 事件驱动的迁移 | `A --> B: 事件[守卫]/动作` |
| 复合状态 | 状态内的子状态机 | `state 名 { ... }` |
| choice | 动态分支 | `<<choice>>` |
| fork/join | 并发分叉/汇合 | `<<fork>>` / `<<join>>` |

## 3. 转换语义

- `事件`：触发条件（「支付成功」）；
- `[守卫]`：必须满足的布尔条件（`[金额<10000]`）；
- `/动作`：转换的副作用（`/通知用户`）；
- 事件驱动 vs 条件驱动：事件是外部信号，守卫是内部判断——两者可组合。

## 4. 复合状态与并发

```mermaid
stateDiagram-v2
  state 处理中 {
    [*] --> 校验
    校验 --> 执行
    执行 --> [*]
  }
  state 并行 {
    -- 区A
    A1 --> A2
    -- 区B
    B1 --> B2
  }
```

- 复合状态：内部有完整子状态机（可含自己的初/终态）；
- 并发：`--` 分隔并行区（区域间无交互）。

## 5. 状态建模要点

- **状态 vs 事件混淆**：状态是名词（`已支付`），事件是动词（`支付成功`）；
- 状态完整性：每个可达状态都有出口（或终态）；
- 状态爆炸：>10 状态拆子状态机；
- 状态机是测试路径设计的金标准（覆盖所有转换）。

## 6. Mermaid 表达要点

- `stateDiagram-v2`（勿用旧 `stateDiagram`）；
- 转换标签 ≤20 字符（`事件[守卫]/动作` 三段压缩）；
- 完整语法见 howto/09。
