# 状态机图（09-state-machine-diagram）

## 1. 适用场景

对象生命周期、状态转换规则、事件驱动系统、测试路径设计。**状态语义**——关注「对象在什么状态、什么事件触发转换」。

## 2. 基本语法

```mermaid
stateDiagram-v2
  [*] --> 待支付
  待支付 --> 已支付: 支付成功
  待支付 --> 已取消: 用户取消
  已支付 --> 已发货: 发货
  已发货 --> 已完成: 确认收货
  已取消 --> [*]
  已完成 --> [*]
```

- 初态 `[*]`（只有一个）；终态 `[*]`（可多个）；
- 转换：`状态A --> 状态B: 事件[守卫]/动作`；
- 转换标签格式：`事件`、`事件[条件]`、`事件/动作`、`[条件]/动作`。

## 3. 守卫与动作

```mermaid
stateDiagram-v2
  待审核 --> 已通过: 审核[金额<10000]/通知用户
  待审核 --> 需人工: 审核[金额>=10000]
  需人工 --> 已通过: 人工通过
```

- 守卫 `[条件]` 决定分支；动作 `/动作` 为转换副作用；
- 条件写清楚（`[金额>=10000]`），不写「审核失败」这种含糊词。

## 4. 复合状态

```mermaid
stateDiagram-v2
  [*] --> 处理中
  state 处理中 {
    [*] --> 校验
    校验 --> 执行
    执行 --> 校验: 重试
    执行 --> [*]
  }
  处理中 --> 完成
  处理中 --> 失败
  完成 --> [*]
  失败 --> [*]
```

## 5. fork/join 与 choice

```mermaid
stateDiagram-v2
  state 分叉 <<fork>>
  state 汇合 <<join>>
  state 选择 <<choice>>
  运行 --> 分叉
  分叉 --> 任务A
  分叉 --> 任务B
  任务A --> 汇合
  任务B --> 汇合
  汇合 --> 选择
  选择 --> 成功: [全部ok]
  选择 --> 部分失败: [有失败]
```

## 6. 并发（复合状态内 `--`）

```mermaid
stateDiagram-v2
  state 并行处理 {
    -- 区A
    A1 --> A2
    -- 区B
    B1 --> B2
  }
```

## 7. 注释

```mermaid
stateDiagram-v2
  已支付
  note right of 已支付: 支付成功后的状态，可发起退款
```

## 8. 布局与美观

- 状态 ≤10；转换 ≤20；超限按子状态机拆分；
- 状态名 = 名词短语（`已支付`），事件 = 动词短语（`支付成功`）；
- 主路径直线，异常路径靠边；
- 常见错误：漏了终态、事件与状态名混淆、守卫含糊。

## 9. 常见陷阱

- 把业务流程画成状态机（事件 vs 步骤混淆）；
- 状态与转换标签语义混写；
- 复合状态嵌套超过 2 层。
