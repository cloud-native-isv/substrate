# 语义分析与意图理解（00）

## 1. 输入类型分类

| 输入类型 | 特征 | 处理方式 |
|---------|------|---------|
| 直接描述 | 「画一个订单系统的时序图」 | 提取实体与关系，直接绘图 |
| 图片复刻 | 提供截图/已渲染图，要求「复刻」「转成 Mermaid」 | 识别图中元素与布局，转成对应 Mermaid 类型（先看 SKILL.md 类型对照表） |
| 模糊描述 | 「帮我画个架构图」 | 交互式提问（AskUserQuestion ≤4 问）确认：目标读者/抽象层级/单图或图集 |
| 代码可视化 | 提供源码/配置文件 | 静态分析代码结构 → classDiagram/flowchart；勿臆造未出现的类/关系 |
| 文档驱动 | 提供需求文档/设计文档 | 产出上下文摘要，绘图对着摘要 |

## 2. 上下文摘要（文档/代码类输入必做）

带出处（文件:行号）的摘要，包含：
- **组件清单**：名称、职责、出处；
- **关系清单**：依赖/调用/数据流、出处；
- **核心流程**：关键时序/状态流转，出处；
- **关键决策**：影响结构的决定，出处。

摘要服务于「程序整体正确、不臆造」：图里每个元素都能溯源。

## 3. 差距分析

用户描述 vs 可绘图信息之间常存在差距：
- 用户说「系统」但没给模块——区分「可推断」与「需确认」；
- 关系方向不明（A 依赖 B 还是 B 依赖 A）——标问号，不硬猜；
- 数量不明（N 个节点还是 1 个）——用 `×N` 占位并注明。

## 4. 交互式确认（最多一轮 ≤4 问）

提问优先级：
1. 目标读者与用途（技术评审/汇报/教学）→ 决定抽象层级；
2. 单图还是图集 → 决定拆分；
3. 必须包含的元素 → 防止漏画；
4. 风格约束（配色/语言/主题）。

## 5. 输出

Step 1 产出（写入工作区供后续步骤使用）：
- 上下文摘要（若输入丰富）；
- 确认后的绘图意图（一句话）；
- 不确定项清单（含默认假设）。
