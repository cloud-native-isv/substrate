# 大图专项（large-diagram-playbook）

> 节点多（>15）、层次多或尺寸大的复杂图专用。先读第 0 步，再按五步技术栈执行。

## 第 0 步：先做 UML 语义分析，再绘图

大图最容易变成「方框堆砌」。动手前先回答：
- **图类型**：这个内容该用哪类图？（flowchart / classDiagram / stateDiagram-v2 / erDiagram / gantt …）
- **元素种类**：组件/节点/存储/接口/状态/任务——种类即语义；
- **关系类型**：依赖/关联/实现/基数/转换——关系不可混用；
- **构造型与接口**：`<<interface>>` 等标注对外契约。

语义分析不过关，五步美化只是把错误画得更好看。

## 五步技术栈

### 1. 「×N」语义折叠

- N 份同类兄弟 → 1 个代表节点 + `×N` 标注（`API网关 ×8`）；
- 批次/流水线 → 单节点 + 说明注释；
- 折叠后节点数仍 >15 的，回到「减法与拆分」拆图集。

### 2. 弱化管线，突出语义色

- 非关键连线统一浅灰虚线（`-.->` + `linkStyle ... stroke:#bbb`）；
- 语义色只给关键路径/关键节点（classDef 集中定义）；
- 目标：读者 3 秒内看出「重点在哪」。

### 3. 字号层级

- `%%{init: {themeVariables: {fontSize: "14px"}}}%%` 基准；
- 层级：标题 > subgraph 容器 > 元素 > 注释 > 图例；
- 禁用内联字号/加粗；大图可整体降 1-2px 换取版面。

### 4. subgraph 分层控宽高比、消交叉

- 按架构接缝分层（入口层/业务层/数据层/基础设施层）；
- 每层一个 subgraph，层间连线即主数据流；
- 单 subgraph 内节点 ≤6，超出拆子图；
- 交叉线：调整方向（TD↔LR）、重排声明顺序、或拆分。

### 5. 长文本移入 legend / 图集文字

- 元素标题 >10 字符的：精简标题 + 图内 `legend` 或图集文字解释；
- legend 是「单一细节仓」：所有补充信息集中放，不散落节点上；
- flowchart 用 `legend` / `legendRight` 指令定义图例块。

## 大图专用自检清单

- [ ] 语义分析（图类型/元素/关系/构造型）先做了吗？
- [ ] 核心元素 ≤7、总节点 ≤15（折叠后）？
- [ ] ×N 折叠用了单代表 + 标注吗？
- [ ] 非关键管线弱化（灰虚线）？关键路径有语义色？
- [ ] 字号层级统一？无内联字号？
- [ ] subgraph 分层清晰、层内 ≤6、交叉可控？
- [ ] 长文本都在 legend/图集文字里？
- [ ] **只用 SVG 交付**（大图 PNG 易超限/被裁）？PNG 也同时产出供预览？
- [ ] 用 measure-svg-layout.py 量过版面（WBS/甘特）？
