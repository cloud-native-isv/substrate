# 内容指南（content）

## 1. 内容组织

### 1.1 单一职责

- 每张图只回答**一个问题**：结构？流程？状态？时序？部署？
- 一张图同时画「组件结构 + 时序 + 状态」是反模式——拆图集。

### 1.2 C4 分层（架构叙事）

- 需要多层抽象时按 C4 递进：上下文（Context）→ 容器（Container）→ 组件（Component）→ 部署（Deployment）；
- 每层单独成图，层间交叉引用（`▶ 见图N`）；
- 小系统用 1-2 层即可，勿为分层而分层。

### 1.3 元素数量控制

- 核心元素 ≤7（硬上限 ≤15）；
- 超限先做减法（删非核心），再考虑拆分；
- 一对多画「单代表 + `×N` 标注」，不画 N 份兄弟盒。

## 2. 标签与注释

### 2.1 标签精简（≤10 字符）

- 元素标题 ≤10 字符（CJK）/ ≤12 字符（英文）；
- **先去重**：图类型/构造型/嵌套已表达的语义删掉；
- 禁止在标题里塞句子。

### 2.2 注释策略

| 场景 | 方式 |
|------|------|
| 边上的简短说明 | `A -->|说明| B`（≤10 字符） |
| 完整句子/段落 | note（sequence `note`、class `note for`） |
| 图例/全局说明 | flowchart `legend` 指令 |
| 长文档说明 | 图集文字（HTML 段落），图内只留 `▶ 见文字` |

### 2.3 标识符规范

- 节点/类/参与者 id 用英文短标识（`OrderService` / `s1`），显示文字用 `as` / 引号标题：
  - `participant OS as 订单服务`
  - `class 订单 { ... }`（中文类名直接可用）
  - flowchart 用 `id["中文标题"]`；
- id 稳定（跨图复用），显示文字可变——保证图集交叉引用可维护。

## 3. 协作与维护

- 源文件 `.mmd` 随图保存（可 diff、可复渲）；
- 每图一个文件，文件名即图名（`figure-01-order-flow.mmd`）；
- 图集共享词汇：编号、颜色、构造型跨图同义（复制同一 init 与 classDef 段）；
- 改动后重渲并核对「自足性 + 交叉引用 + 跨图一致」。
