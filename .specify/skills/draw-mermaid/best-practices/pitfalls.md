# draw-mermaid 陷阱（Pitfalls）

> 从 viz-skill-arena 竞技 cycle（Substrate 架构图，2026-08-07）中 R1 评审实测发现的坑。每条含「现象 → 后果 → 规避」。最佳实践见 [best-practices.md](best-practices.md)。

## 1. 全图默认同色（视觉单调）

**现象**：所有子系统/容器未做 `classDef` 定制，渲染后全是一片默认蓝。
**后果**：读者无法靠颜色区分语义族，评审降视觉分。
**规避**：多子系统必配 classDef 色相族 + legend 图例。

## 2. 子系统纵向堆叠导致跨层连线交叉

**现象**：5 个子系统按列表顺序纵向堆叠，枢纽子系统被埋在中间，跨层边 N×M 全互联。
**后果**：连线交叉密集、视觉凌乱，信息组织被评「偏弱」。
**规避**：改中心辐射（hub-and-spoke）布局，跨层边经枢纽汇聚。

## 3. 容器框内长文本渲染截断

**现象**：C4 容器描述塞入多行长文本（如把调度策略、存储 key 格式全写进框）。
**后果**：渲染时框内文字拥挤甚至截断，图不可读。
**规避**：框内只放 2-3 行关键词，详情下移 HTML 说明。

## 4. 按直觉选图型，漏交付需求图

**现象**：任务要求 5 类图（组件/部署/序列/状态机/资源模型），只画了"顺手"的 3 类。
**后果**：需求覆盖不全，semantic/requirement-fit 双降分；R1 三个裁判全部点名此问题。
**规避**：绘制前按需求清单列图型映射表，逐项勾选（状态机用 `stateDiagram-v2`、资源模型用 flowchart/C4 分层）。

## 5. HTML 不含图源与渲染命令

**现象**：只交付渲染后的 HTML/PNG，`.mmd` 源码与渲染脚本调用缺失。
**后果**：无法复现、无法修改重渲，reproducibility 降分。
**规避**：HTML 内嵌 .mmd 全文 + `render-mermaid.sh` 命令。

## 6. 序列图遗漏关键分支

**现象**：5 阶段主流程画全了，但关键分支（如池饱和请求 parking、CAS 冲突重试）只在文字描述里。
**后果**：语义不完整——评审明确要求补 opt 块。
**规避**：序列图阶段设计时同步列出分支/异常路径，用 opt/alt 块入图。

## 7. 渲染宽度过窄挤压文字

**现象**：宽图用默认渲染宽度，节点边框与文字间距被压缩（如 824px 宽）。
**后果**：小屏下文字重叠，部署图可读性差。
**规避**：宽图提高渲染宽度/字号参数后重渲。

## 8. 状态机只放文字 note 不放图

**现象**：状态机以序列图底部一行文字摘要（`[*]→SUSPENDED→…→[*]`）代替独立图。
**后果**：需求「状态机图」未真正交付；状态语义（含 CRASHED 人工介入态）表达不完整。
**规避**：状态机一律用独立 `stateDiagram-v2`，人工介入态显式标注。
