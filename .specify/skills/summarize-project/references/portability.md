# 跨层规范：可移植性纪律 —— 优化的是**技能能力**，不是"在某个项目上的表现"

`summarize-project` 的**跨层强制规范**，同时约束**技能作者**（写规则的人）与**执行器**（在某个项目上跑这个技能的人）。工作流主框架见 [../SKILL.md](../SKILL.md)；判定规则见 [consistency-rules.md](consistency-rules.md)；缺料降级见 [degradation.md](degradation.md)；opt-in 取材见 [source-tiers.md](source-tiers.md)。

**本文档存在的原因**：这个技能是在少数几个真实项目上迭代出来的。迭代过程会不断产生形如"实测 `[X]` 867 条、`[x]` 239 条""3 提交 / 跨度 2 天""`src/*.rs` 一个模块 = 一个子任务"的观察。**这些是某个项目某一天的事实，不是规则**。一旦被写成看起来通用的规则，技能就从"能力"退化成"对那两个项目的过拟合"——换个项目就给出错误的默认假设、错误的路径、错误的语言细节。本文档给出一条硬底线：**规则必须项目无关；任何具体值必须显式标注为示例并由确定性依据实测得出。**

---

## 1. 规则 vs 示例：判据与写法

### 1.1 判据（一句话）

> **"换一个项目就不成立"的内容，就不是规则。**

具体地，下列内容**一律不得**以规则形态出现（不得作为判据、不得作为默认假设、不得被别处引用为依据）：

| 类别 | 反例（不得作为规则） | 正确形态 |
|------|----------------------|----------|
| **实测计数/比例** | "`[X]` 867 条、`[x]` 239 条""31 个 spec、38 个特性" | 规则写"两种写法都要计入、比例由脚本实测"；具体数字标 `示例（本值随项目而变，须实测）` 或直接删除 |
| **阈值** | "3 提交 / 2 天算材料过弱""里程碑 ≥4 个且跨度 ≥2 个月才独立成图" | 阈值只存在于**脚本内的常量**，文档只写"取引擎 `<字段>`"；文档不复述任何阈值数字 |
| **路径/文件名** | "读 `.specify/memory/features.md` 的第 5 列""`Cargo.toml` 的 `[package]`" | 规则写**材料类别 + 定位判据**；具体路径标为"示例布局"，并说明"该路径不存在时按类别另找等价材料" |
| **语言/生态细节** | "模块树 = `src/*.rs`""子命令 = `#[derive(Subcommand)] enum` 变体" | 先给语言无关判据（[source-tiers.md](source-tiers.md) §3.1 的 C1–C4），再用**对照表**列各生态等价物，并声明表非穷举 |
| **模块名/特性 ID/spec key** | 把某项目的真实模块名、特性名、spec 目录名写进规则（形如"`<模块>.rs` 对应 <某组件> 读取""`F-0NN` = <某特性名>"） | 用占位符 `<模块文件>` / `<FID>` / `<slug>`；需要举例时明写"示例，随项目而变" |
| **人名/邮箱** | 真实姓名与邮箱 | 一律占位（`<规范名>`）或使用明显虚构的示例名；**真实邮箱绝不写进技能文档**（隐私收敛同时适用于技能自身） |
| **某项目的特有结论** | "本项目 001/002/003/006 判 completed""README 的 help 少列了 `cat` 子命令" | 抽成规则（"代码与 help 不一致时以代码为准"），案例只作**形态示例**且去掉专有名词 |

### 1.2 示例的三条写法要求

被保留下来的具体值**必须同时**满足：

1. **显式标注**：紧邻处写明 `示例` / `虚构样例` / `形态模板`，并说明"本值随项目而变、须实测"；
2. **不被引用为依据**：任何规则、判据、检查项都**不得**以示例值为前提（示例是给人看形态的，不是给判定用的）；
3. **可替换**：把示例换成另一组值，周围的规则文字**不需要改**——如果需要改，说明规则里混进了示例。

**样例文件**（`templates/project-input.example.yaml` 等）内容可以具体、可以逼真，但：文件头必须声明它是**虚构样例**；文档**不得**把样例里的字段值（阶段划分、日期、人名、计数）当作规则依据引用；样例只用于试跑与自检。

## 2. 任何判定必须有确定性依据

**"经验值"不是依据。** 技能里的每一个判定，其依据只能来自下列四类之一：

| 依据类型 | 例子 | 为什么可移植 |
|----------|------|--------------|
| **DB 约束** | 非空、唯一、外键、日期合法性、枚举、无出处数字拒收（`../schema/project.sql`） | 装载即校验，与项目形态无关 |
| **SQL 查询** | 计数、聚合、天数差、时间轴排序 | 同一份数据必得同一结果 |
| **脚本输出字段** | 引擎 `status` / `progress_pct` / `delay_days` / `gantt_recommended` / `coverage.*`；`check-coherence.py` 的 FAIL/WARN | 阈值与算法都在脚本内，文档不重述 |
| **材料明写** | 表单字段值、管理系统导出、文档里明写的百分比 + `progress_source` | 有出处、可溯源、可复核 |

**禁止的依据形态**：

- ❌ "在某个项目上观察到 X，所以默认 X"——过拟合；
- ❌ "通常 / 一般 / 大多数项目会…"——无出处的先验；
- ❌ "看起来 / 目检觉得 / 凭经验"——不可复现（**渲染后的几何目检除外**，那是对已生成产物的确认，且有量测脚本兜底）；
- ❌ 把示例值当阈值现场比较（如"提交数只有 3，比示例里的 3 一样少，所以过弱"）。

## 3. 执行器在新项目上的行为准则

技能规则与目标项目的材料形态**不匹配**是正常情况（不同的管理系统、不同的工件布局、不同的语言、不同的状态词）。此时：

1. **不硬套规则**：示例路径不存在 ⇒ 按材料**类别**另找等价物；找不到 ⇒ 如实记为缺口。**不得**因为"文档里的路径不存在"就断言"该项目没有这类材料"，也**不得**为了套用规则而把不同性质的材料硬当成规则里的那种材料。
2. **不套用示例值**：任何计数、比例、阈值一律在目标项目上现取；**不得**沿用文档示例或上一个项目的值。
3. **如实记录到材料缺口**：规则与该项目材料形态不匹配时，在 `## 元信息 · 材料缺口` 记一行——「缺什么」写**该规则需要而本项目没有的材料类别**，「已检索来源」写**实际找过的路径/命令**（证明找过），「报告影响」写**因此哪一段降级或不存在**（结构见 [degradation.md](degradation.md) 第 6 节）。
4. **状态词按目标项目定义**：状态字面量的语义**以目标项目自身的定义为准**（[consistency-rules.md](consistency-rules.md) §1.1），差异写进表单 `status_map`，实际映射表落进 `## 元信息 · 状态映射`；**不套用默认表的直觉**。
5. **呈现决策必须可复现**：出图与否、人员是否标注、图集是否拆分、里程碑是否独立成图、进度条出不出——一律按各文档给出的**确定性裁决规则**判，并把命中的条件/步骤号记入 `## 元信息`。**同一技能 + 同一输入 + 同一基准日，两次运行的呈现结果必须一致**；发现某处需要"临场决定"，即为规则缺口，按 [consistency-rules.md](consistency-rules.md) §9.3 处理（类推并登记 / 澄清 / 记 `unknown`），**不得**静默自选一种。

## 4. 技能作者的自检（改这个技能时必过）

- [ ] 新增/修改的每条规则，**换一个项目仍然成立**（换项目后不需要改这条规则的文字）
- [ ] 新增的每个具体数字/路径/文件名/语言细节/模块名/ID/人名，**要么删除，要么显式标注为示例**并说明须实测
- [ ] 新增的每个判定都能指名到 §2 的四类依据之一；没有"经验值"判定
- [ ] 新增阈值**只**写进脚本常量，文档里不出现该数字
- [ ] 新增的"可以 A 或 B"型表述**全部**带确定性裁决规则（明确条件 → 明确选择），或删掉其中一个选项
- [ ] 样例文件已声明为虚构样例；没有任何文档把样例值引用为规则依据
- [ ] 同一规则只有一个权威出处（不新增第二张映射表/第二套阈值/第二条判据）

## 5. 落盘门禁（本次运行必过）

**可移植性自检**（写入 `## 元信息`，与其余落盘门禁同级；清单入口见 [reporting-playbook.md](reporting-playbook.md) §7）：

- [ ] 本次报告里的每个数字/日期/天数/百分比都来自引擎输出或材料明写，**没有**沿用技能文档里的示例值
- [ ] 本次实际使用的取材点按**类别判据**定位（不是照抄某个语言/框架的示例路径）；示例路径不存在时已按类别另找或记入缺口
- [ ] 规则与本项目材料形态不匹配之处**已逐条记入 `### 材料缺口`**（而不是硬套规则或静默跳过）
- [ ] 全部呈现决策（出图与否 / 人员标注 / 图集拆分 / 里程碑图选型 / 进度条）均有确定性依据并已记入 `## 元信息`，**无临场取舍**
- [ ] 状态映射用的是本项目自身口径（`status_map` 覆盖已记录），未套用默认表直觉
