# 复杂大型图表美化 Playbook（Large / Complex Diagram Playbook）

> **何时用**：节点/簇多、渲染尺寸巨大（如 SVG 一边 > 20000px 或 PNG 触及 4096 硬上限）、一眼难以解析的架构/部署/组件大图。
> **核心原则**：对复杂大图，**美观度与低心智负担优先**——整洁的大图靠「少而清晰」取胜，而非「全部塞进画布」。
> **说明**：以下为图表类型无关的抽象技术；代码均为**通用示意**（占位名如「实例/服务 A/节点」），套用时按领域替换。

---

## 前置：先套用通用绘图原则

大图美化之前，**先按 [diagram-principles.md](diagram-principles.md) 的四步顺序做完前两步**（这些原则图表类型无关，不只适用于大图）：
1. **UML 语义先行**——选对图类型、用对元素种类与关系类型、补构造型/接口（[principles §1](diagram-principles.md)）。
2. **视觉语义**——角色即位置 / 一对多的表达 / 关联即同色 / 分组即框选 / 文字即负担 + **元素标签最小化规则**（[principles §2–§3](diagram-principles.md)）。

> **纯绘图技巧有天花板；先把建模与达意做对，再谈美化。** 以下五步是**大图特有**的美化技术栈。

---

## 五步技术栈（按收益排序）

### 1. 「×N」语义折叠——最大心智负担收益
镜像/重复的结构（多副本、多可用区、多实例、重复的同构切片）**不要逐份画出**。折叠为**一份参数化代表** + 显式多重性标注：

```plantuml
' ❌ 逐份铺开：实例 1 一套、实例 2 一套……画布翻倍、模式重复
' ✅ 折叠为一份代表，用 «×N» 表达可扩展性
frame "重复子系统 «×N»\n(实例 1│2│…│N 同构)" as slice {
  component "组件 A" as a
  component "组件 B" as b
}
```

- **前提**：被折叠项确实同构。折叠是**呈现压缩，不是信息删除**。
- **保真兜底**：把被折叠掉的不变式（如「N 套相互独立」「共享/隔离关系」）写进 **legend 一行**，并在标题/标签用 `«×N»` 明示，**防止被误读为单实例**。
- 收益：对重复结构大图，折叠可一次性大幅缩小画布，通常是单项最大提升。

### 2. 弱化管线、突出语义色——让关键路径「跳出来」
大图里连线极多，默认同色会糊成一团。**把默认箭头调成中性灰，只给有语义的关键路径上色**：

```plantuml
skinparam ArrowColor #A3B1BA          ' 默认连线：中性灰，退后
' 关键路径显式着色（与 legend 对应）
svcA -[#6A1B9A,thickness=2]-> store : 关键路径①
svcB -[#C62828,thickness=2]-> svcA  : 关键路径②
```

- 定一套「角色→色相」映射并固定语义（如：结构容器中性灰、核心服务一色、数据存储一色、外部依赖一色……）。**色相承载语义，而非装饰。**
- **保色渲染（确定化·防单色吞噬）**：若渲染管线对 UML 默认**强制单色**（如注入 `skinparam monochrome true`，仅当检测到色彩标记才跳过），语义色会被吞掉且结果随 agent/渲染次数**随机抖动**。**确定性保色配方（必做）**：源中同时放 **`skinparam monochrome false`** 且在 legend/元素放**至少一处 `<color:#..>` 标记**（两者任一即触发「检测到色彩→跳过单色」，都放最稳）；渲染时**输入与输出用不同 basename**，避免同名覆盖使二次渲染丢标记。→ 每次都稳定出彩色。

### 3. 字号层级——建立视觉层次
标题 > 框标题 > 节点 > 组件 > 制品 > 边标签，用递减字号 + 粗细拉开层级：

```plantuml
skinparam TitleFontSize 30
skinparam TitleFontStyle bold
skinparam rectangleFontSize 17
skinparam nodeFontSize 15
skinparam frameFontSize 14
skinparam componentFontSize 13
skinparam ArrowFontSize 11
skinparam ArrowFontColor #455A64        ' 边标签压暗，退到背景层
```

### 4. 正交路由 + 隐藏边锚点——消交叉、控宽高比
大图最大的丑源是**长距离斜拉的交叉连线**与**失衡的宽高比**（过高/过瘦要么触 PNG 上限、要么滚动疲劳）：

```plantuml
skinparam linetype ortho                ' 正交折线，边贴边走，天然减少交叉
' 用隐藏边把「本应同排」的元素拉到同一 rank，避免纵向拉长
extA -[hidden]right-> extB              ' 游离元素排成一行
mainBox -[hidden]right-> auxBox         ' 主体与辅助并排
skinparam ranksep 40
skinparam nodesep 26
```

- **目标宽高比**：尽量接近 **4:3 横向**（一屏可纳），而非细长竖条。正交路由 + 隐藏边通常能把竖长图拉成横向、消除大部分交叉。
- 若相邻性冲突（消 A 交叉会引 B 交叉），**优先保住语义关键路径相邻**，次要边可容忍一处穿越。

#### 4b. 连线治理细则（当「结构已清晰但线条仍乱」时）
结构到位后，交叉引用的线常仍杂乱。按以下五条专治连线（均为**只改边、不动结构/配色**的低风险手术）：

1. **显式端口/方向提示**：给纠缠的边加 `-up->` / `-down->` / `-left->` / `-right->`（含着色形式 `-[#C62828,thickness=3]right->`），引导 ortho 把边铺成平行/正交段，而非默认斜穿。
2. **并行语义边打捆**：同一对区域间的多条同组关键边走**同侧、同端口、同走向**，读作「一组通道」，而非散落交叉。
3. **边贴边（boundary-hugging）正交路由**：长边沿框边 / 边距走，进目标框时汇成平行线；避免从画布中央斜切。
4. **借「簇间沟槽(gutter)」走线**：若某条边穿过了框的**标题带**，把它抬到相邻簇之间的空隙（gutter）里走——既清标题带，又不新增交叉。
5. **反例警示**：宽图上不要用 `skinparam linetype polyline`——它会让 Graphviz 把图重排成细长竖版，破坏横版结构。**宽图坚持 `ortho`**。
6. **`ortho` 崩溃回退（稳定性）**：`skinparam linetype ortho` 在**嵌套 cluster + 边直接指向 cluster/frame 节点**时可能**确定性崩 GraphViz**（`DotStringFactory.solve` 异常，产出非空错误图）。两条防御：(a) 让边只连**叶子组件**、不直连 frame/cluster；(b) 若仍崩，**回退默认 spline 路由**（去掉 `ortho`）——实测回退后不仅不崩、宽高比往往还更好。渲染后必检产出不是错误图。
> 根因优先：多数交叉源自「边跨越相距很远的簇」。**先用隐藏边把两端簇挪到相邻**（见 §4 隐藏边锚点），交叉往往自然消失，胜过逐条改边。

#### 4d. 多平面部署图·按平面分带（band-by-plane）
当一张**部署图**把多个治理/控制平面（如「声明式·低频·入库」vs「命令式·高频·带外」）叠加在同一套运行拓扑上，最大丑源是两族治理边**斜穿全图相互交叉**。按平面分水平带根治：
- **一平面一横带，按生命周期/频率排序**：低频/声明带在上、高频/运行带在下（自上而下读＝配置期→运行期），运行拓扑落最下带。
- **枢纽 vs 折叠落位**：每租户控制面折为**单一 «×N» 代表**居一侧；共享 DaemonSet/守护实例作**单一枢纽（不 «×N»，因跨租共用）**居另一侧——「每租 N 份 vs 全局 1 份共享」靠左右分立 + «×N» 有无一眼可辨。
- **治理边分侧竖直下行（杜绝交叉）**：每族边固定一条竖直沟槽（声明族走一侧、命令族走另一侧），贴带边平行下行、天然不交叉；跨带边只发生在**相邻带之间**，绝不纵贯全图。
- 入口 actor 只喂顶带；用 `-[hidden]down->` 把「actor→顶带→…→底带枢纽」锚成竖直主轴锁定带序，配 `linetype ortho`。
- **隐藏堆叠轴只连「左列→左列」**：锁带序的隐藏主轴必须从每带**最左列**的节点竖直下行到下一带**最左列**节点；**绝不右列→右列**——右列是治理边/数据边的出口侧，隐藏轴走右列会与真实边抢同一沟槽、把右列元素拽离语义位置，实测会把分带布局拉垮。左列是入口侧、语义上本就是「喂下一带」的位置。
> 此启发式经「改技能→重生成部署图→评分」闭环验证：平面分离与消交叉显著改善。

#### 4e. 分带图的宽高比预算（band aspect budget）——把「近正方形」压成 4:3 横版
band-by-plane（§4d）竖直堆带，堆到 2–3 带时最易堆成**近正方形**（~1.0）、且引擎可能把平面**退化成左右并置**。用「宽高比预算」压回 ~4:3 横版并锁住分带：
- **每带宽高比预算 ≈ 目标总比 × 带数**：目标总 W/H≈1.33，B 条带各占 ~1/B 高度，故**每条带自身应做到 ≈ 1.33×B**（B=2→~2.7:1，B=3→~4:1）——每带要「宽而扁」。
- **带数阈值**：只在 **B ≤ 3** 竖直堆带；第 4 个平面**不再堆第 4 带**，改把最高带横向拆成并列子列、或合并相邻平面。
- **带内水平打包（令 `nodesep ≥ ranksep`，反转常规间距比）**：每带内对等簇/节点用隐藏 `right` 链串成单行；单行带＝最扁。**但一行最多 ~5 个节点**——**超过必须折成 2×N 网格**（列数 ≈ `round(sqrt(该带节点数))`），**严禁一长行**：一长行会把整图拉成 2.5:1+ 的细长横条，是宽高比失控（及「稳定性」抖动）的头号成因。
- **带内并列 vs 堆叠判据**：兄弟簇**无直接依赖边**→并列；仅当一簇喂另一簇**且该带已超宽度预算**才纵向堆叠。
> 一句话：分带图变方/被拉成左右并置，几乎总因带内被折成多行或间距比偏纵向；**先把每带压成单行宽扁、再令 `nodesep ≥ ranksep`**，即回落 4:3。经闭环验证：加入此预算后重生成部署图，分带稳定立住且宽高比达标。

#### 4c. 隐藏脚手架重排全局版面——能做什么 / 不能做什么
「铺一层不可见元素，靠其重排规划整页布局」是常见诉求。实测在 Graphviz(默认引擎) + 嵌套 cluster 下，**边界清晰**：

- ✅ **跨列「肋网格」对齐同类行**：给不同列中语义同层的节点串**跨列隐藏边**（如 `rowX_c1 -[hidden]right-> rowX_c2 -[hidden]right-> rowX_c3`），可把多列的**对应行拉到同一水平线**，同层连线走平、整体层高可降约一成。这是隐藏脚手架**真正有效**的用法。
- ✅ **游离元素单行带**：`a -[hidden]right-> b -[hidden]right-> c` 把游离元素收成一行。
- ✅ **锁定列序 / 纵向顺序**：隐藏链防止 Graphviz 漂移。
- ❌ **跨 cluster 强制 same-rank**：无法把分处不同 cluster 的多列**顶端**拉到同一 rank——只要存在真实跨列依赖边（上游→下游），Graphviz 的 rank 分配就会让下游列**天然低一秩**，呈阶梯状；强行加锚点只会打乱列序、把外围元素甩到角落，**净负收益**。
- ⚠️ **不要为此改布局引擎**：`!pragma layout elk` 正交路由更干净，但可能把本已调好的**横版重排回细长竖版**，宽图上得不偿失；如需 ELK 请两版都渲、按宽高比取舍。

> 经验法则：隐藏脚手架用于**对齐同类行 / 收拢游离元素 / 锁序**收益稳；用于**推翻依赖边决定的 rank 结构**会撞墙。想更进一步只能改语义画法（拆依赖）或拆分多图。

### 5. 长文本移出画布——legend 作单一「细节仓」
画布上只留**极简标签**（如 `①–⑥` 编号、短名）；把所有解释性长文（通道语义、不变式、术语表）收进**一个紧凑 legend**：

```plantuml
legend right
|= 通道 |= 语义 |
| ①–⑥ | 见下 |
| «×N» | 同构多实例，图示其一，可扩展至 N |
endlegend
```

- 边标签保持裸编号，语义查 legend——画布清爽，细节不丢。

> **反模式：不要把元素内文本外置为 per-element `note` + 连线牵引。** 直觉上「外置文本 → 盒子变小 → 更好对齐」，但在**嵌套 cluster 大图**上是净负收益：PlantUML 会**忽略 `note left/right/top/bottom of` 的方位提示**、把 note 甩到页面边缘，连线随之**横穿整幅画布**；外置 N 个元素 = **新增 N 条连线**，重新制造交叉。**盒子瘦身的正确落点是 legend（本节）或去重（见 principles §3），不是浮动 note。**

---

## 落地顺序（推荐）
1. 先做 **①×N 折叠**（结构性收缩，收益最大）；
2. 再上 **④正交路由 + 隐藏边**把宽高比调成横向、消交叉；
3. 然后 **②弱化管线 + ③字号层级 + ⑤legend** 做视觉收尾；
4. **只用 SVG 交付**大图（PNG 有 4096 硬上限会裁剪/糊化，见 [layout.md](layout.md) PlantUML Server 限制一节）——**评分/评审也看 SVG 原图**，不要对着触顶的 PNG 打分：PNG 在 4096 上限处被压缩或裁边，美观/清晰度评分会被渲染假象带偏，SVG 才是布局的真实呈现。

## 自检清单（大图专用）
- [ ] 有无镜像/重复结构可折叠为 «×N»？折叠后不变式是否在 legend 明示？
- [ ] 默认连线是否已弱化为中性灰、关键路径是否着色且与 legend 对应？
- [ ] 是否存在长距离斜拉交叉连线？能否用 `linetype ortho` + 隐藏边消除？
- [ ] 宽高比是否接近横向一屏（避免细长竖条 / 触 PNG 上限）？
- [ ] 画布上是否残留长句注释？能否移入 legend？
- [ ] 交付是否为 SVG？
